# 算法与 C 程序设计初步

### 2.1 算法的含义

算法中，有些步骤的次序是不能颠倒的

解决同一问题可以有多种算法，要根据具体需要选择

> *最高效的算法不一定是最合适的*

***一个算法往往可解决一类问题，而不仅仅是一个具体问题***

***应对有规律的问题设计循环算法以简化操作步骤***

- 确定性

- 可执行性

- 有**零个或多个**输入，**一个或多个**输出

> *注意算法可能没有输入，但一定有输出*

#### 2.3.3 变量

每次运行程序时，操作系统都会将程序指令加载到计算机内存中，以更有效地工作

> 8 个二进制位 *Bit* 组成的 **1 Byte** 即是一个内存单元
>
> 每个内存单元都有自己**唯一确定**的内存地址，通常用*十六进制码* 表示
>
> 由于 Bit 只能取值 `0/1`，因此 Byte 取值为 `-128~127` 或 `0~255`，以此类推
>
> $$
> 1\ GB=1024\ MB=1024^2\ KB=1024^3\ B=8\times1024^3\ b
> $$
>
> 额外注意，不要混淆 **一个二进制位 Bit** 和 **一个内存单元比特 Byte**

*用户对于内存单元没有直接的使用权*，**变量**是高级语言赋予用户申请内存使用权的一个途径，具有**非破坏性读出**、**破坏性写入**的基本特征

`long int` 等特殊类型变量可存取更大范围，但也降低了运算速度

***浮点数据也称为实型数据***

#### 2.5.1 数据类型

##### 1. 整型数据

绝大多数计算机均采用**二进制补码**存储整型数据

- 正数：*原码、反码、补码均相同*

- 负数

  - 原码：*其相反数的最高位改为 1，因此该位又称符号位*

  - 反码：*符号位不变，其余位取反*

  - 补码：*反码加 1*

| 13 的二进制码  | 0 000 0000 0000 1101     |
| -------------- | ------------------------ |
| **-13 的原码** | **1 000 0000 0000 1101** |
| **-13 的补码** | **1 111 1111 1111 0011** |
| **-13 的反码** | **1 111 1111 1111 0010** |
| **-1 的原码**  | **1 111 1111 1111 1111** |

##### 2. 实型数据

C 语言未具体规定实型数据所占字节数，亦未规定具体小数和指数部分的位数

对于一般而言

- **小数部分越多**，数据表示的**精度越高**

- **指数部分越多**，表示的**数据范围越大**

一般认为，`float` 型的有效数字为 **7~8 位**，`double` 型的有效数字为 **15~16 位**

#### 2.5.4 自增和自减运算符

区分*先自增，后使用* 和*先使用，后自增*，如 $i=10$，$j=8$

- 打印 `i++` 和 `++j`，得到 `10` 和 `9`

- 令 `k=i++`，打印 `k` 得到 `10`

- 令 `k=(++j)*3`，打印 `k` 得到 `27`

#### 2.9.2 比较两个交换变量值的算法

如若交换两个整型变量 `a` 和 `b` 的值

- 传统的**临时变量法**

  - 定义一个 `t` 临时存储 `a`

  - 把 `b` 赋值给 `a`，再把 `t` 赋值给 `b`

- **迭代法**

  - 保存两数之和到 `a`

  - 从两数之和 `a` 中减去 `b`给 `b`

  - 从两数之和 `a` 中减去新 `b`—也就是 `a` 给 `a`

```cpp
int t = a;
a = b, b = t;
```

```cpp
a = a + b;
b = a - b;
a = a - b;
```

迭代法的**可读性要差一些**。程序设计时，应当**先考虑程序的清晰性**，不要刻意追求技巧。不要为了省略一个工作单元而写出可读性差的算法

### 2.10 课外学习

##### 变量命名技巧

- **匈牙利命名法**

  `int: iCount` `string: strName`

  - 因其可读性和易于维护，曾经被广泛作为标准采用

  - 现在已经因为 IDE 的进化而逐渐被淘汰

  > *翻阅一些古早代码时，会发现它真的随处可见！*

- C / Python 常见的**蛇形命名法** *Snake Case*

  `user_name` `MAX_SPEED`

- Java / C# 等面向对象语言常见的**驼峰命名法** *Camel Case*

  `firstName` `UserProfile`

- URL / 文件名常见的**烤串命名法** *Kebub Case*

  `user-profile.html` `get-user-data`
